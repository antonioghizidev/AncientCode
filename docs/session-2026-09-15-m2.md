# Sessão 2026-09-15 — M2 tool loop

> Resumo exclusivo desta sessão. Metodologia: `specs/methodology.md`.

## Objetivo da sessão

Implementar o **M2 — Tool loop** (`specs/milestones/02-m2-tool-loop.md`): registry de tools,
filesystem confinado, tool `shell` com `ask`, loop multi-turno com gate de aprovação e teto de
iterações, fallback JSON (§4.3) e scan de exfiltração (§5.6.4).

## O que foi feito

- `internal/tools` — interface `Tool`, `Registry` determinístico, nome estrito
  (`^[a-z][a-z0-9_]*$`), `UnmarshalStrict`, limite de args (256 KiB), helper `Raw`.
- `internal/tools/files` — `read_file`/`write_file`/`list_dir` com `filepath.Clean` + prefixo +
  `EvalSymlinks`, blocеio de segmentos sensíveis (`.ssh`, `.aws`, `.env*`, `shadow`, ...),
  redação na leitura, limite de conteúdo de escrita (8 MiB).
- `internal/tools/shell` — desabilitada por default; hard-block em forma normalizada
  (sobrevive a aspas/encadeamento), negação de `; && || | & \n $() \``, `bash -c` com contexto,
  saída limitada, exit code.
- `internal/loop` — multi-turno: `planCalls` (valida+escaneia+aprova **antes** de persistir/
  executar), `Approver` injetável (allow/ask/deny), resultado truncado+redigido+etiquetado
  `[untrusted-tool-output]`, system prompt de hierarquia efêmero, teto de 20 iterações,
  fallback JSON (`auto`/`always`/`never`) reutilizando o mesmo pipeline.
- `cmd/ancientcode` — registry montado por toolbox_mode (`plan`/`run`), approver y/N no stdin,
  versão `0.2.0-m2`.
- Note: `toolbox_mode=plan` default já oculta `write_file`/`shell` do payload (gate rígido do
  M3 adiantado na forma de política `ask`).
